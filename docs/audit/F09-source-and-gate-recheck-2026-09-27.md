# F09 数据源核查、业务任务与 Gate 复核（2026-09-27）

后续 F09 目标 Gate 不再要求验证三种不同数据库身份；此变更不代表 Runtime/Execution 受限角色的安全验收通过。当前目标配置见 [容量监控运行手册](../runbooks/f09-capacity-monitor.md)。

## 1. 完成概况与证据边界

依据 [F09 规格](../SumAlpha-QuantOS-Development-Plan.md#task-f09)及[固定 22 点初审](F09-comprehensive-review-2026-09-27.md)。本次直接连接已配置的测试阶段 Supabase PostgreSQL，只读取 `information_schema.tables`、`pg_matviews` 和秘密元数据的列名；未读取秘密值或业务行。目录检查发现 `quantos` 只有 `execution_secret_refs` 与 `secret_references` 两个相关元数据表，**没有 Realtime 配额数据表、风险物化视图或运营聚合视图**。仓库检索也未发现这些采集/刷新业务任务或秘密轮换执行入口。这是本次目标目录及源码的结论，不外推为 Supabase 平台没有相应能力。

本轮将 Runtime 之外的 `SupabaseStorageAdapter::upload_and_register`、`get_artifact_recorded`、`delete_artifact_recorded` 接到真实操作结果采样。测试 Supabase Storage 往返与 PostgreSQL 断言通过：上传、下载、删除各有一条 `0` 样本，缺失对象读取有一条 `1` 样本。该路径与 Runtime 原有采样均不记录对象 key、HTTP body 或凭据。通用未记录版 `get_artifact`/`delete_artifact` 仍可由其他调用方使用，因此不能声称所有未来 Storage 入口已覆盖。

**F09/F0 Gate 继续关闭。**按固定分母，当前源码及组件证据可确认 **2/22 完全满足（9.1%）**、19 项部分满足、1 项缺正式验收回执。部分项不折算放行率。`c38cb4044b3cae1dca2dfab6da1181eaede5a3cd` 的测试 Supabase **组件目标 Gate PASS**，但回执明确 `f09Accepted=false`；同完整 SHA CI、Nightly 及最终目标验收 PASS 回执尚未取得。按用户当前验收范围，**同地域运行目标与查询 P95 硬性基准不再是 F09 Gate**；本机到 Supabase 的 968.11225ms 历史值只保留诊断。规格中的 300ms 持续 15 分钟指标采样、告警规则与真实告警回执仍须验证。

后续目标复测发现测试 Supabase 会偶发在**建立 TLS 连接时**关闭会话，使同一组内不同用例在业务断言前失败。只对建连增加最多四次、每次相隔两秒的有限重试；查询、故障注入和断言不重试。重跑 `make test-f09-live` 的三项当前 Gate 用例 **3/3 PASS**，其中一次建连在第二次成功。这是组件复测，仍须在提交后的完整 SHA 下取得整个目标 Gate 回执。`gh auth status` 显示当前 GitHub CLI token 无效；在重新配置认证前，不能触发或读取远程 CI/Nightly 回执。

逐项续审：02 的 live BFF/Runtime 和市场/组合批处理写入口现要求绝对、可写的 trace 路径；无路径时市场命令实测在写出文件前拒绝，正常市场参考摄取返回的 correlation ID 与两条 JSONL trace 一致。组合持久化、BFF 会话以及 Execution 正式入口仍缺业务事实到 trace 的双向回执，因此 02 仍为**部分**。03 的只读探针在 `1f7221ea20ad231c871375dfa1dd237850cd534b`、2026-09-27T12:08:04Z 直连测试 Supabase：九类指标最近 90 秒均为 **0 条**；最近 24 小时仅投影、风险输入查询、组合查询和 Storage 四类有样本。回执为 `FAIL`，见忽略目录 `artifacts/f09/source-coverage.json`；样本计数不证明业务来源。目标库未启用 `pg_cron`/`pg_net`，仓库也无部署中的刷新 worker，03 仍为**部分**。

源覆盖探针已接入 F09 远程目标工作流：组件探针之后无条件运行，九类来源缺采样会使工作流失败；失败时两类回执仍上传。配置静态检查校验执行顺序与失败上传。此接线只保证缺口可见，不把样本存在当成业务来源证明，也不改变 03、22 的未关闭状态。
