# F06-A09 开发机远程鉴权延迟 Gate 范围修订

> 日期：2026-09-25。用户确认本地网络原因，要求将开发机跨区域 P95 从 F06 验收 Gate 移除，并以其余条件完成 F06 验收。本修订承接[先前移除同区域 Gate 的记录](./F06-A09-gate-scope-correction-2026-09-25.md)；历史回执和失败值不改写。

## 决定与适用范围

F06 服务端验收继续要求真实 Supabase Auth/OIDC 与 BFF/Runtime 身份闭环、独立 Execution/Vault 受控命令链，以及请求、数据库、角色拒绝矩阵。新总回执采用 `quantos-f06-target-acceptance/v2`，必须绑定当前完整 SHA、状态为 `PASS`、`failures=[]`，上述三组各为 `PASS`；全部 A01–A10 为 `CLOSED` 且工作树干净。`make f06-acceptance-gate` 仍按缺失或失败回执拒绝放行。

开发机跨区域 100 次鉴权读 P95 `<500ms` 不再是 F06/A09 放行条件。独立的 `make f06-auth-latency-check` 保留为按旧阈值运行的可选诊断命令，其成功或失败均不参与新版总 Gate。首次同区域部署后的 P95 `<100ms` 仍是独立部署性能目标，不由本次范围修订判为通过。

## 原因与诊断证据

| 来源 | 样本 | P95 | 结论 |
|---|---:|---:|---|
| `40300445da8aed0f874aa1f5369b5e42bdf11234` 的已同步 v1 总回执 | 100 次鉴权读 | 670.556ms | 旧范围 FAIL |
| 同 SHA 后续两次受限 BFF 登录、验证 TLS 的鉴权读 | 各 100 次 | 701.1ms、815.425ms | 均超过旧 `<500ms` Gate |
| 同一受限登录、单连接 `SELECT 1` | 100 次 | 789.226ms | 最简单数据库往返也有长尾 |
| 固定两个 Pooler DNS 地址的 `SELECT 1` | 各 100 次 | 806.816ms、893.157ms | 未定位到单个异常地址 |

本机到目标库的默认路由经 `ipsec0`；物理网卡 `en0` 的少量 TCP 建连对照没有改善。上述探针说明授权 SQL 复杂度不足以单独解释当前长尾，但没有精确定位网络、Pooler 或数据库内部的贡献。未修改 VPN、系统路由、数据库角色、TLS 或鉴权实现；不以反复采样直到偶然通过的结果替代稳定验收。

## 验收与风险边界

1. 原 F06-A09 按用户确认的范围修订保持 `CLOSED`；该状态不表示当前开发机 P95 达标。旧范围 v1 FAIL note 和旧基线 v1 PASS note 继续保留，可按完整 SHA 追溯。
2. 新版总 Gate 不能接受 `status=FAIL` 的回执，也不能复用其他 SHA 的目标结果。修改文档或脚本后，须在新提交上重跑三组目标检查，再写入并同步 v2 Git note。
3. 部署性能风险仍存在。首次同区域部署时必须单独测量、记录运行区域与目标库区域，并在不达标时调查连接路径及数据库负载；此项不影响 F06 当前服务端范围验收。
4. Terminal 浏览器、MFA 页面交互、全部页面 API 联调属于 Web 阶段；正式受限 Runtime Storage 凭据、X03 可信传输及新建参考库 schema diff 保持各自独立边界。
