## A07：完整持久化覆盖率

新增 `make f05-db-coverage`、`make f05-target-coverage`，对 PostgreSQL 集成、Storage HTTP 故障与库测试统一插桩。目标 Gate 另包含实际 Supabase Storage 集成测试。nightly 使用前者并启用 `QUANTOS_F05_BRANCH=1`，不再排除适配器。

覆盖率校验动态枚举两个 crate 的全部 `src/**/*.rs`；缺文件、重复文件、无效计数、比例不一致均拒绝。总体要求 line ≥90%、region ≥85%，nightly branch ≥85%；三个持久化适配器还须分别满足 line ≥90%、region ≥85%。新增负向测试防止高核心覆盖率掩盖未测试适配器。

本机 PostgreSQL 17.11、nightly 插桩结果：

| 源文件 | line | region |
|---|---:|---:|
| event/src/lib.rs | 95.95% | 95.41% |
| event/src/pg.rs | 93.66% | 87.16% |
| storage/src/lib.rs | 99.45% | 98.68% |
| storage/src/pg.rs | 96.33% | 90.48% |
| storage/src/snapshot.rs | 93.62% | 92.90% |
| storage/src/supabase_storage.rs | 99.25% | 96.53% |
| 全范围 | **95.10%** | **92.33%** |

全范围 branch：**109/126 = 86.51%**。无 F05 源文件排除。HTTP 故障服务器覆盖认证头、上传/下载、哈希校验、403/404/500、网络失败以及 PostgreSQL 注册失败后的删除补偿；它不是 Supabase 托管服务回执。连接模式分支仅对明确 `sslmode=disable` 的 loopback 测试库运行。

## A09：真实消费与量化回执

沿用正式 `PgEventStore::poll_outbox_once` 万条消费测试，新增实际测量 JSON；数据库及目标 Gate 先删除旧测量，再强制读取并校验新测量，写入绑定 SHA 的总回执。

本机实测：10,000 个唯一副作用、10,000 条 dispatched outbox、10,000 条 applied inbox；checkpoint=10,001；pending inbox/outbox/dead letter 均为零。消费 10.297s；完整客户端取回 10,000 条 correlation 事件链 **91.115ms**，满足 ≤5 秒要求。消费时长不属于五秒查询指标。

回执拒绝事件数量不足、错误 checkpoint、非正式消费者、服务端 EXPLAIN 计时、缺失或超限查询时长。未改写完成状态制造验收结果。
