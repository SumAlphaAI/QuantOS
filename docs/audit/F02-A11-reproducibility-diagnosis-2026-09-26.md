## 三、问题清单及风险分析

| 优先级 | 模块 | 具体表现 | 影响与状态 |
|---|---|---|---|
| 中危 | F01/F02 Terminal 构建 | 历史同源三次构建输出不同，尚未定位原因 | A11 整体保持 OPEN；重复成功不能消除偶发风险 |
| 中危，已修复 | F01 诊断证据 | 只保存摘要，销毁原始 Web 内容 | 新正式 workflow 保留每轮原始输出并上传，即使比较失败也能取证 |
| 验收前置项 | main 收尾 | 仍缺修复后同一 main SHA 的完整 8 项检查及正式签名下载 | 不能将 PR merge SHA 或诊断 SHA 的成功拼接成主线验收 |

新增留存代码会校验复制结果与已验证摘要一致，拒绝复用同名快照目录；每次正式调用撤销旧快照。四项测试证明字节差异仍按原规则失败，输出留存不会放宽 Gate。

独立 Web 诊断 workflow 改为手动触发，接受完整源码 SHA 与 2–20 次新鲜构建参数，默认当前检出。移除硬编码旧 main SHA、每次 PR 自动重复诊断和临时压缩器作业。它不作为 required check，也不替代正式 F01。

## 四、下一步整改与关闭条件

1. 后续出现差异时，直接下载同一运行的 `f01-reproducibility-evidence`，比较回执对应的两份 chunk，再向压缩前模块与依赖关系回溯。此次历史失败的第一份字节未留存，无法从 SHA 摘要还原。
2. 捕获可重现条件后实施针对性修复，增加能够在旧实现失败、修复后通过的回归；不提前关闭模块优化或更换压缩器来掩盖未知原因。
3. 固定修复后的 PR head，取得其 required checks；合入 main 后取得新的完整 main SHA，重新取得 8 项成功及正式下载验签回执，才关闭 A11 并将 F02 标记 ACCEPTED。

当前交付是已证实的 Playwright 修复与证据留存修复；**未交付未经验证的构建根因修复，也未宣称 A11 关闭。**
