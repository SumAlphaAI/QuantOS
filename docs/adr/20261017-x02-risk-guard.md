# ADR: X02 scoped risk authority and current kill revision

Status: implemented for local development; deployment and formal acceptance pending.

The legacy engine accepts booleans and unverified approval text, computes a public checksum and maps lifetime portfolio P&L to daily loss. It remains a compatibility fixture, with its portfolio adapter corrected to require an explicit daily value. X02 introduces a separate typed `RiskGuard` so legacy X03 fixtures cannot accidentally be relabeled as keyed risk authority.

The authority binds F06 identity, X01's complete risk snapshot and S03's verified, approved target to a signed decision. Equity/day/quote/venue are separate trusted backend inputs. Policy values are signed with all rule outcomes and source hashes. HMAC domains separate approvals, kill receipts and decisions; no production signing key is created or inspected. A generic nonempty approval string is never authorization.

Clones share one mutex for kill CAS, review time and duplicate admission. Deny takes precedence over approval; only Allow reserves a pre-trade key. Approvals bind the request and forbid self-approval. Every kill revision invalidates outstanding Allows, and decision expiry cannot exceed any source/approval expiry. This supplies a deterministic local linearization point, not a durable distributed transaction with an issuer. Global means the configured authority's accounts, not every independent tenant/process in a deployment. X03 must own atomic current-risk/approval/command consumption; a disconnected validate-then-submit call is insufficient.

The implementation retains f64 valuations and conservative gross projection in one quote unit. Lifetime realized P&L is never treated as daily loss or equity. Reducing orders may conservatively deny; no optimistic netting is assumed. Deployments need trusted financial/day/quote sources and independently verified clocks, scoped keys/rotation, identity revocation, record retention/capacity, durable fail-closed kill startup and cross-process consistency. These are explicit target/Beta obligations, along with original P95 <1s, not silently waived acceptance criteria.

Local admission requires a new frozen 41-node/135-group dependency closure and >=95% actual LLVM rule-branch coverage with raw evidence. It publishes only X02 DEVELOPMENT READY. All 24 target groups, actual Supabase, distributed recovery, same-SHA hosted CI and ProjectUser confirmation remain independently required. No order, database service or external release is introduced.
